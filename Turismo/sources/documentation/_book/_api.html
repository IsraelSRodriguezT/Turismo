4  Documentación de API

4.1 Introducción a la API

La API de PIT es una API REST construida con Django REST Framework que implementa: - Autenticación con JWT - Paginación de resultados - Filtrado y búsqueda - Validación de datos - Estructura de respuesta estándar

4.2 Base URL

http://localhost:8000/api

En producción:

https://api.turismo.local/api

4.3 Autenticación

4.3.1 Tokens JWT

Todos los endpoints (excepto login y registro) requieren autenticación con JWT.

4.3.1.1 Obtener Token (Login)

POST /api/usuarios/login/
Content-Type: application/json

{
  "email": "usuario@ejemplo.com",
  "password": "contraseña123"
}

Respuesta exitosa (200):

{
  "success": true,
  "message": "Inicio de sesión exitoso",
  "data": {
    "access": "eyJ0eXAiOiJKV1QiLCJhbGc...",
    "refresh": "eyJ0eXAiOiJKV1QiLCJhbGc...",
    "usuario": {
      "id": 1,
      "email": "usuario@ejemplo.com",
      "nombre": "Juan Pérez",
      "rol": "ADMINISTRADOR"
    }
  }
}

4.3.1.2 Usar Token en Requests

Incluir en header Authorization:

GET /api/atractivos/
Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGc...

4.3.1.3 Renovar Token (Refresh)

POST /api/token/refresh/
Content-Type: application/json

{
  "refresh": "eyJ0eXAiOiJKV1QiLCJhbGc..."
}

Respuesta:

{
  "access": "eyJ0eXAiOiJKV1QiLCJhbGc...",
  "refresh": "eyJ0eXAiOiJKV1QiLCJhbGc..."
}

4.4 Estructura de Respuesta

4.4.1 Respuesta Exitosa (2xx)

{
  "success": true,
  "message": "Operación realizada exitosamente",
  "data": {
    "id": 1,
    "nombre": "Atractivo Turístico",
    "descripcion": "Descripción del atractivo"
  },
  "errors": null,
  "meta": {
    "timestamp": "2026-06-22T10:30:00Z",
    "version": "1.0.0"
  }
}

4.4.2 Respuesta con Error (4xx, 5xx)

{
  "success": false,
  "message": "Error de validación",
  "data": null,
  "errors": {
    "code": "VALIDATION_ERROR",
    "details": [
      {
        "field": "nombre",
        "message": "El nombre es obligatorio"
      }
    ]
  },
  "meta": {
    "timestamp": "2026-06-22T10:30:00Z"
  }
}

4.4.3 Respuesta Paginada

{
  "success": true,
  "data": [
    { "id": 1, "nombre": "Atractivo 1" },
    { "id": 2, "nombre": "Atractivo 2" }
  ],
  "meta": {
    "pagination": {
      "count": 50,
      "next": "http://localhost:8000/api/atractivos/?page=2",

4.5 Códigos HTTP y Estados

Código Significado Caso de Uso
200 OK GET exitoso, actualización exitosa
201 Created Creación de recurso exitosa
204 No Content Eliminación exitosa
400 Bad Request Datos inválidos
401 Unauthorized Token inválido o expirado
403 Forbidden Permisos insuficientes
404 Not Found Recurso no existe
409 Conflict Duplicidad (ej: email ya existe)
422 Unprocessable Entity Validación de campos falla
500 Internal Server Error Error del servidor

4.6 Endpoints Principales

4.6.1 1. Autenticación

4.6.1.1 POST /api/usuarios/login/

Iniciar sesión - Auth: No requerido - Body: email, password

4.6.1.2 POST /api/usuarios/register/

Registrar nuevo usuario - Auth: No requerido - Body: email, password, nombre

4.6.1.3 POST /api/token/refresh/

Renovar token - Auth: No requerido - Body: refresh token

4.6.2 2. Atractivos Turísticos

4.6.2.1 GET /api/atractivos/

Listar atractivos - Auth: Requerido (JWT) - Query params: - page: Número de página (default: 1) - page_size: Resultados por página (default: 10) - canton: Filtrar por cantón (ID) - clasificacion: Filtrar por clasificación - estado: PUBLICADO, BORRADOR, REVISION, ARCHIVADO - search: Búsqueda por nombre

Ejemplo:

GET /api/atractivos/?canton=1&estado=PUBLICADO&page=1

Respuesta:

{
  "success": true,
  "data": [
    {
      "id": 1,
      "nombre": "Cascada del Pailon",
      "descripcion": "Hermosa cascada natural...",
      "latitud": -0.5234,
      "longitud": -78.1234,
      "canton": "Baños",
      "clasificaciones": ["Naturaleza", "Cascada"],
      "estado": "PUBLICADO",
      "fecha_creacion": "2026-01-15T08:00:00Z"
    }
  ],
  "meta": {
    "pagination": {
      "count": 25,
      "total_pages": 3,
      "page_size": 10
    }
  }
}

4.6.2.2 POST /api/atractivos/

Crear nuevo atractivo - Auth: Requerido (GESTOR_TURISTICO, ADMINISTRADOR) - Body: nombre, descripcion, latitud, longitud, canton_id, etc.

Ejemplo:

{
  "nombre": "Nuevo Atractivo",
  "descripcion": "Descripción detallada",
  "latitud": -0.5234,
  "longitud": -78.1234,
  "canton_id": 1,
  "estado": "BORRADOR"
}

4.7 Ejemplos de Integración

4.7.1 JavaScript/Axios

import axios from 'axios';

const API_URL = 'http://localhost:8000/api';
let token = null;

// Login
async function login(email, password) {
  const response = await axios.post(`${API_URL}/usuarios/login/`, {
    email,
    password
  });
  token = response.data.data.access;
  return response.data;
}

// Obtener atractivos
async function getAtractivos(page = 1, canton = null) {
  const config = {
    headers: { Authorization: `Bearer ${token}` }
  };
  const params = { page };
  if (canton) params.canton = canton;
  
  const response = await axios.get(`${API_URL}/atractivos/`, { 
    ...config,
    params
  });
  return response.data;
}

// Crear atractivo
async function createAtractivo(data) {
  const config = {
    headers: { Authorization: `Bearer ${token}` }
  };
  
  const response = await axios.post(`${API_URL}/atractivos/`, data, config);
  return response.data;
}

4.7.2 cURL

# Login
curl -X POST http://localhost:8000/api/usuarios/login/ \
  -H "Content-Type: application/json" \
  -d '{"email":"user@ejemplo.com","password":"password123"}'

# Obtener atractivos
curl -X GET http://localhost:8000/api/atractivos/ \
  -H "Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGc..."

# Crear atractivo
curl -X POST http://localhost:8000/api/atractivos/ \
  -H "Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGc..." \
  -H "Content-Type: application/json" \
  -d '{
    "nombre": "Nuevo Atractivo",
    "descripcion": "Descripción",
    "latitud": -0.5234,
    "longitud": -78.1234,
    "canton_id": 1
  }'

4.8 Paginación

La mayoría de endpoints que retornan listas soportan paginación.

Query parameters: - page: Número de página (default: 1) - page_size: Resultados por página (default: 10, máximo: 100)

Ejemplo:

GET /api/atractivos/?page=2&page_size=20

Meta information:

"meta": {
  "pagination": {
    "count": 50,
    "total_pages": 3,
    "page_size": 20,
    "next": "http://localhost:8000/api/atractivos/?page=3",
    "previous": "http://localhost:8000/api/atractivos/?page=1"
  }
}

4.9 Filtrado y Búsqueda

La mayoría de endpoints soportan filtrado y búsqueda.

Filtrado:

GET /api/atractivos/?canton=1&estado=PUBLICADO

Búsqueda de texto:

GET /api/atractivos/?search=cascada

4.10 Rate Limiting

El sistema implementa rate limiting para prevenir abuso: - Límite: 1000 requests por hora por usuario - Header: X-RateLimit-Remaining
