1 Introducción

PIT (Plataforma Interactiva de Turismo) es un sistema integral de gestión y visualización de información turística georreferenciada para provincias. El sistema integra un poderoso backend basado en Django REST Framework con un frontend moderno construido en React, permitiendo que administradores, gestores territoriales, investigadores y turistas interactúen con información turística de manera intuitiva y eficiente.

1.1 Características Principales

  • 🗺️ Mapas Interactivos: Visualización geoespacial de atractivos turísticos
  • 🎯 Gestión de Atractivos: Registro, edición y publicación de atractivos georreferenciados
  • 🛣️ Rutas Turísticas: Creación y gestión de rutas temáticas
  • 📊 Inventario Digital: Gestión completa de fichas de inventario turístico
  • 👥 Gestión de Usuarios: Control de acceso basado en roles y permisos
  • 🔍 Búsquedas Avanzadas: Filtros por cantón, categoría, servicio y más
  • 📱 Responsive Design: Compatible con navegadores y dispositivos móviles
  • 🔐 Autenticación JWT: Sistema de seguridad basado en tokens JWT

2 Arquitectura del Sistema

2.1 Visión General

PIT implementa una arquitectura modular de tres capas con separación clara de responsabilidades:

┌─────────────────────────────────────────────────────────────┐
│                    CAPA DE PRESENTACIÓN                      │
│  (React Frontend + Interfaz Web + Responsive Design)        │
└────────────────────────────┬────────────────────────────────┘
                             │ JSON/HTTPS
┌────────────────────────────▼────────────────────────────────┐
│                    CAPA DE APLICACIÓN                        │
│  (Django REST API + Lógica de Negocio + Servicios)          │
│  - Views (Controladores HTTP)                               │
│  - Serializers (Validación y Transformación)                │
│  - Services (Lógica de Negocio)                             │
│  - Auth (Autenticación y Autorización)                      │
└────────────────────────────┬────────────────────────────────┘
                             │ ORM/SQL
┌────────────────────────────▼────────────────────────────────┐
│                    CAPA DE DATOS                             │
│  (SQLite Database + Modelos de Datos)                        │
└─────────────────────────────────────────────────────────────┘

2.2 Componentes Principales

2.2.1 1. Frontend (React)

Ubicación: templates/frontend_react/src/

Responsabilidades: - Interfaz de usuario interactiva - Manejo de estado global (Context API) - Enrutamiento de páginas (React Router) - Consumo de API REST - Visualización de mapas interactivos

Stack Tecnológico: - React 18.3.1 - React Router DOM 6.30.0 - Axios para HTTP - Tailwind CSS para estilos - Vite como bundler

Estructura de Carpetas:

src/
├── components/        # Componentes reutilizables
├── pages/            # Páginas de la aplicación
├── routes/           # Configuración de rutas
├── services/         # Servicios API
├── hooks/            # Custom hooks
├── contexts/         # Context API
├── utils/            # Funciones utilitarias
├── App.jsx          # Componente raíz
└── index.js         # Punto de entrada

2.2.2 2. Backend (Django REST Framework)

Ubicación: Turismo/

Responsabilidades: - Lógica de negocio - Procesamiento de datos - Persistencia en base de datos - Autenticación y autorización - Integración con servicios externos (INAMI, ECU 911)

Aplicaciones Django (apps/):

2.2.2.1 a) Usuarios (apps/usuarios/)

  • Gestión de perfiles de usuario
  • Autenticación y roles
  • Permisos y restricciones

Modelos: - Persona: Información de usuario - Usuario: Extensión con roles

2.2.2.2 b) Atractivos (apps/atractivos/)

  • Registro y gestión de atractivos turísticos
  • Clasificación y categorización
  • Servicios asociados
  • Horarios de funcionamiento

Modelos principales: - AtractivoTuristico: Atractivo base - Clasificacion: Categoría del atractivo - Servicio: Servicios ofrecidos - Horario: Horarios de operación - Ruta: Rutas turísticas

2.2.2.3 c) Geolocalización (apps/geolocalizacion/)

  • Datos geográficos y territoriales
  • Información de cantones y provincias
  • Coordenadas y límites

Modelos: - Canton: División territorial - Provincia: Región administrativa - Ubicacion: Coordenadas geoespaciales

2.2.2.4 d) Inventario (apps/inventario/)

  • Gestión de fichas digitales
  • Importación desde Excel
  • Catálogos de inventario

Modelos: - FichaInventario: Registro de inventario - CatalogoInventario: Clasificaciones

2.2.2.5 e) Investigación (apps/investigacion/)

  • Registro de proyectos de investigación
  • Publicación de resultados
  • Vinculación con contenidos

Modelos: - Investigacion: Proyecto de investigación - Resultado: Resultados de proyectos

2.2.3 3. Base de Datos (SQLite)

Ubicación: Turismo/db.sqlite3

Características: - Almacenamiento relacional - Integridad referencial - Índices optimizados - Migrations versionadas

Tablas principales: - usuarios_persona: Datos de usuarios - atractivos_atractivo: Atractivos turísticos - atractivos_clasificacion: Clasificaciones - atractivos_servicio: Servicios - atractivos_horario: Horarios - atractivos_ruta: Rutas - geolocalizacion_*: Datos geográficos - investigacion_*: Proyectos de investigación

2.3 Flujo de Datos

1. Usuario interactúa en Frontend (React)
   ↓
2. Frontend envía solicitud HTTP a Backend (API)
   ↓
3. Django recibe y valida autorización (JWT)
   ↓
4. View procesa y delega a Service
   ↓
5. Service ejecuta lógica de negocio
   ↓
6. Models interactúan con Base de Datos (ORM)
   ↓
7. Backend retorna respuesta JSON
   ↓
8. Frontend recibe datos y actualiza UI

2.4 Patrones de Diseño Utilizados

2.4.1 1. MVC (Model-View-Controller)

  • Models: Definición de entidades en models.py
  • Views: Controladores HTTP en views.py
  • Controllers: Lógica en services.py

2.4.2 2. Service Layer

  • services.py en cada app contiene lógica de negocio
  • Desacoplamiento entre views y modelos
  • Reutilización de lógica

2.4.3 3. Serializer Pattern

  • serializers.py valida y transforma datos
  • Serialización de modelos a JSON
  • Deserialización de requests

2.4.4 4. Repository Pattern

  • ORM de Django actúa como repositorio
  • Abstracción de acceso a datos
  • Queries centralizadas

2.4.5 5. Context API (Frontend)

  • Gestión de estado global
  • Autenticación centralizada
  • Compartir datos entre componentes

2.5 Integraciones Externas

2.5.1 1. INAMI - Servicio de Clima

Endpoint: Servicio REST de datos climáticos Uso: Obtener información meteorológica Frecuencia: On-demand desde Frontend

2.5.2 2. ECU 911 - Estado de Vías

Endpoint: Servicio REST de estado vial Uso: Información de seguridad y estado de carreteras Frecuencia: On-demand

2.6 Seguridad

2.6.1 Autenticación

  • JWT (JSON Web Tokens)
  • Tokens con expiración
  • Refresh tokens para renovación
  • Blacklist de tokens revocados

2.6.2 Autorización

  • Sistema de roles y permisos
  • Decoradores en views
  • Validación en services

2.6.3 Protección de Datos

  • HTTPS en producción
  • CORS configurado
  • Validación de inputs
  • SQL Injection prevención (ORM)

2.7 Escalabilidad

Consideraciones de diseño: - Separación de capas permite escalar independientemente - Stateless API facilita horizontalización - Índices en base de datos para queries complejas - Posibilidad de migrar a PostgreSQL - Caché con Redis (futuro)

3 Guía de Instalación

3.1 Requisitos del Sistema

3.1.1 Software Requerido

  • Python 3.10 o superior
  • Node.js 16 o superior
  • npm o yarn
  • Git
  • SQLite (incluido en Python)
  • Navegador moderno (Chrome, Firefox, Safari, Edge)

3.1.2 Requisitos de Hardware

  • Procesador: Dual-core 2GHz o superior
  • RAM: Mínimo 2GB (4GB recomendado)
  • Almacenamiento: 500MB para instalación completa

3.1.3 Sistema Operativo

  • Windows 10/11
  • macOS 10.14+
  • Ubuntu 18.04+

3.2 Instalación del Backend (Django)

3.2.1 Paso 1: Clonar o Descargar el Repositorio

cd c:\ruta\a\tu\carpeta
git clone <url-repositorio>
cd Turismo-develop/Turismo

3.2.2 Paso 2: Crear Entorno Virtual

3.2.2.1 En Windows:

python -m venv venv
venv\Scripts\activate

3.2.2.2 En macOS/Linux:

python3 -m venv venv
source venv/bin/activate

3.2.3 Paso 3: Instalar Dependencias de Python

pip install --upgrade pip
pip install -r requirements.txt

Paquetes principales instalados: - Django 6.0.4 - Django REST Framework - djangorestframework-simplejwt - drf-spectacular - django-filters - python-decouple

3.2.4 Paso 4: Verificar Instalación

python manage.py --version

3.2.5 Paso 5: Ejecutar Migraciones (Base de Datos)

python manage.py migrate

Este comando: - Crea la estructura de tablas en SQLite - Aplica todas las migraciones pendientes - Inicializa la base de datos

3.2.6 Paso 6: Crear Superusuario (Administrador)

python manage.py createsuperuser

Se te pedirá: - Username: (tu nombre de usuario) - Email: (tu correo) - Password: (contraseña segura) - Password (again): (confirmar contraseña)

3.2.7 Paso 7: Verificar Estructura de Base de Datos

python manage.py dbshell

Dentro de SQLite:

.tables

Verás todas las tablas creadas.

3.2.8 Paso 8: Iniciar Servidor Django

python manage.py runserver

El servidor estará disponible en:

http://localhost:8000
Admin: http://localhost:8000/admin
API: http://localhost:8000/api

3.3 Instalación del Frontend (React)

3.3.1 Paso 1: Navegar a la Carpeta Frontend

cd templates/frontend_react

3.3.2 Paso 2: Instalar Dependencias de Node

# o si usas yarn:

Crear archivo .env en la carpeta frontend_react:

npm --version

3.3.5 Paso 5: Iniciar Servidor de Desarrollo

npm run dev

El frontend estará disponible en:

http://localhost:5173

3.3.6 Paso 6: (Opcional) Compilar para Producción

npm run build

Crea carpeta dist/ con archivos optimizados.

3.6 Troubleshooting

3.6.1 Problema: “ModuleNotFoundError” en Python

Solución:

pip install -r requirements.txt

3.6.2 Problema: “Cannot find module” en Node

Solución:

rm -rf node_modules package-lock.json
npm install

3.6.3 Problema: Puerto 8000 o 5173 en uso

Cambiar puerto Django:

python manage.py runserver 8001

Cambiar puerto Vite:

npm run dev -- --port 5174

3.6.4 Problema: Base de datos corrupta

Solución (pierde datos):

rm db.sqlite3
python manage.py migrate
python manage.py createsuperuser

3.6.5 Problema: Errores de CORS

Verificar config/settings.py tenga configurado CORS correctamente:

CORS_ALLOWED_ORIGINS = [
    "http://localhost:5173",
    "http://localhost:3000",
]

4 Documentación de API

4.1 Introducción a la API

La API de PIT es una API REST construida con Django REST Framework que implementa: - Autenticación con JWT - Paginación de resultados - Filtrado y búsqueda - Validación de datos - Estructura de respuesta estándar

4.2 Base URL

http://localhost:8000/api

En producción:

https://api.turismo.local/api

4.3 Autenticación

4.3.1 Tokens JWT

Todos los endpoints (excepto login y registro) requieren autenticación con JWT.

4.3.1.1 Obtener Token (Login)

POST /api/usuarios/login/
Content-Type: application/json

{
  "email": "usuario@ejemplo.com",
  "password": "contraseña123"
}

Respuesta exitosa (200):

{
  "success": true,
  "message": "Inicio de sesión exitoso",
  "data": {
    "access": "eyJ0eXAiOiJKV1QiLCJhbGc...",
    "refresh": "eyJ0eXAiOiJKV1QiLCJhbGc...",
    "usuario": {
      "id": 1,
      "email": "usuario@ejemplo.com",
      "nombre": "Juan Pérez",
      "rol": "ADMINISTRADOR"
    }
  }
}

4.3.1.2 Usar Token en Requests

Incluir en header Authorization:

4.7.1 JavaScript/Axios

import axios from 'axios';

const API_URL = 'http://localhost:8000/api';
let token = null;

// Login
async function login(email, password) {
  const response = await axios.post(`${API_URL}/usuarios/login/`, {
    email,
    password
  });
  token = response.data.data.access;
  return response.data;
}

// Obtener atractivos
async function getAtractivos(page = 1, canton = null) {
  const config = {
    headers: { Authorization: `Bearer ${token}` }
  };
  const params = { page };
  if (canton) params.canton = canton;
  
  const response = await axios.get(`${API_URL}/atractivos/`, { 
    ...config,
    params
  });
  return response.data;
}

// Crear atractivo
async function createAtractivo(data) {
  const config = {
    headers: { Authorization: `Bearer ${token}` }
  };
  
  const response = await axios.post(`${API_URL}/atractivos/`, data, config);
  return response.data;
}

Ubicación: apps/*/views.py

Las views manejan requests HTTP:

from rest_framework import viewsets, status
from rest_framework.decorators import action
from rest_framework.response import Response
from .models import AtractivoTuristico
from .serializers import AtractivoSerializer

class AtractivoViewSet(viewsets.ModelViewSet):
    queryset = AtractivoTuristico.objects.all()
    serializer_class = AtractivoSerializer
    
    def get_queryset(self):
        # Filtrar por cantón si se proporciona
        canton = self.request.query_params.get('canton')
        queryset = super().get_queryset()
        if canton:
            queryset = queryset.filter(canton_id=canton)
        return queryset
    
    @action(detail=True, methods=['post'])
    def enviar_revision(self, request, pk=None):
        """Cambiar estado a REVISION"""
        atractivo = self.get_object()
        atractivo.estado = 'REVISION'
        atractivo.save()
        return Response({
            'status': 'Atractivo enviado a revisión'
        })

Características: - ModelViewSet proporciona CRUD automático - get_queryset() para filtrado personalizado - Decorador @action para endpoints custom - Retorna respuestas JSON

6.4.4 4. Services (Lógica de Negocio)

Ubicación: apps/*/services.py

Los servicios contienen la lógica de negocio, separados de views:

from django.db import transaction
from .models import AtractivoTuristico

class AtractivoService:
    @staticmethod
    def crear_atractivo(datos):
        """Crear atractivo con validaciones de negocio"""
        try:
            atractivo = AtractivoTuristico.objects.create(**datos)
            return atractivo
        except Exception as e:
            raise AtractivoServiceException(str(e))
    
    @staticmethod
    def publicar_atractivo(atractivo_id):
        """Cambiar estado a PUBLICADO"""
        atractivo = AtractivoTuristico.objects.get(id=atractivo_id)
        atractivo.estado = 'PUBLICADO'
        atractivo.save()
        return atractivo
    
    @staticmethod
    def obtener_atractivos_por_canton(canton_id):
        """Obtener atractivos de un cantón"""
        return AtractivoTuristico.objects.filter(
            canton_id=canton_id,
            estado='PUBLICADO'
        )

import React, { createContext, useState } from 'react';

export const AuthContext = createContext();

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const [token, setToken] = useState(localStorage.getItem('access_token'));
  
  const login = async (email, password) => {
    const response = await fetch(`${API_URL}/usuarios/login/`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email, password })
    });
    
    const data = await response.json();
    setToken(data.data.access);
    setUser(data.data.usuario);
    localStorage.setItem('access_token', data.data.access);
  };
  
  return (
    <AuthContext.Provider value={{ user, token, login }}>
      {children}
    </AuthContext.Provider>
  );
}

7 Glosario de Términos

7.1 A

Admin/Administrador
Usuario con permisos máximos en el sistema. Puede gestionar usuarios, aprobar cambios, y acceder a todas las funcionalidades.
API (Application Programming Interface)
Interfaz de programación que permite que diferentes aplicaciones se comuniquen entre sí. En PIT, es la API REST que conecta Frontend con Backend.
Atractivo Turístico
Lugar, sitio o actividad de interés turístico que puede ser visitado por turistas. Registrado en la plataforma con información geolocalizada.
Autenticación
Proceso de verificar la identidad del usuario mediante usuario y contraseña. En PIT se usa JWT (tokens).

7.2 B

Backend
Parte del sistema que procesa datos, ejecuta lógica de negocio y gestiona la base de datos. En PIT: Django REST Framework.
Borrador
Estado inicial de un atractivo o ruta. No es visible al público, permite edición continua.
Bundle
Archivo compilado del frontend que contiene todos los recursos (JavaScript, CSS, imágenes) empaquetados para producción.

7.3 C

Cantón
División territorial administrativa de una provincia. Usado para clasificar y filtrar atractivos.
Clasificación
Categoría asignada a un atractivo (Ej: Naturaleza, Cultura, Aventura). Un atractivo puede tener múltiples.
CORS (Cross-Origin Resource Sharing)
Mecanismo que permite que aplicaciones en diferentes dominios se comuniquen. Necesario para conectar Frontend con Backend.
CRUD
Acrónimo para Create (crear), Read (leer), Update (actualizar), Delete (eliminar). Operaciones básicas en datos.

7.4 D

Dashboard
Panel de control que muestra información resumida y estadísticas del sistema.
Django
Framework de Python para desarrollo web. Usado como base del Backend de PIT.
DRF (Django REST Framework)
Librería que extiende Django para crear APIs REST de manera fácil. Usada para los endpoints de PIT.

7.5 E

Endpoint
URL específica de la API que realiza una acción. Ej: /api/atractivos/ es un endpoint.
Estado
Condición de un contenido. Estados posibles: BORRADOR, REVISION, PUBLICADO, ARCHIVADO.

7.6 F

Frontend
Interfaz de usuario que ves en el navegador. En PIT: React con Tailwind CSS.

7.7 G

Gestor Territorial
Usuario que gestiona información geográfica y administrativa (cantones, provincias, ubicaciones).
Gestor Turístico
Usuario que crea y edita atractivos y rutas turísticas.
Geolocalización
Información de ubicación geográfica (latitud, longitud, coordenadas). Usada para posicionar atractivos en mapas.

7.8 H

Horario
Información sobre cuándo está abierto un atractivo. Puede variar por tipo (normal, fines de semana, feriados).
HTTP
Protocolo de comunicación entre navegadores y servidores. HTTPS es la versión segura (con encriptación).

7.9 I

Investigación/Investigador
Usuario que registra y publica proyectos de investigación y sus resultados.
Inventario
Catálogo de fichas digitales de atractivos turísticos. Puede importarse desde archivos Excel.

7.10 J

JWT (JSON Web Token)
Sistema de autenticación usando tokens encriptados. Usuario recibe token al logarse y lo usa en todas las solicitudes.

7.11 L

Latitud
Coordenada geográfica que indica posición norte-sur (rango: -90 a 90 grados).
Leaflet
Librería JavaScript para crear mapas interactivos. Potencialmente usada en PIT.

7.12 M

Mapas Interactivos
Visualización geográfica donde se pueden ver atractivos, hacer zoom, panear, etc.
Meta
Información adicional en respuestas API (paginación, timestamps, versión, etc.).
Migración
Script que define cambios a la estructura de base de datos. Permite versionar cambios de schema.
ModelViewSet
Clase de Django REST Framework que proporciona automáticamente CRUD para un modelo.

7.13 N

Nivel de Accesibilidad
Indica si un atractivo es de acceso LIBRE, RESTRINGIDO o PAGADO.

7.14 O

ORM (Object-Relational Mapping)
Técnica que permite interactuar con base de datos usando objetos Python en lugar de SQL directo. Django usa ORM.

7.15 P

Paginación
División de resultados en páginas. Mejora performance y UX. Ej: 10 resultados por página.
Permisos
Especificación de qué acciones puede realizar cada usuario según su rol.
Persona
Entidad base que representa un usuario en el sistema. Puede tener información de perfil, email, teléfono.
Payload
Datos principales en una solicitud o respuesta HTTP (no incluye headers ni metadatos).
PostgreSQL
Sistema de base de datos relacional profesional. Recomendado para producción en lugar de SQLite.
Provincia
Región administrativa que contiene múltiples cantones. Ej: Tungurahua.
Publicado
Estado de un contenido que es visible al público y no puede ser editado sin cambiar estado primero.

7.16 Q

Query
Solicitud para obtener datos de base de datos. Ej: “Traer todos los atractivos del cantón Ambato”.
Quarto
Formato de documento que permite combinar código, resultados, texto y visualizaciones. Usado para esta documentación.

7.17 R

React
Librería de JavaScript de Facebook para crear interfaces de usuario interactivas. Usada en el Frontend.
Revisión
Estado intermedio. Contenido en revisión aguarda aprobación del administrador.
Rol
Tipo de usuario que determina qué puede hacer. Ej: Turista, Gestor Turístico, Administrador.
Ruta Turística
Recorrido que conecta múltiples atractivos en una secuencia específica. Incluye información de duración y dificultad.
REST (Representational State Transfer)
Arquitectura para diseñar APIs web. Usa métodos HTTP (GET, POST, PUT, DELETE) sobre recursos.

7.18 S

Serializer
Componente que convierte objetos Python a JSON y valida datos de entrada.
Servicio
Facilidad disponible en un atractivo (parqueo, restaurante, baños, guía, etc.).
SQLite
Sistema de base de datos simple y embebido. Usado para desarrollo. No recomendado para producción.
State Management
Sistema para gestionar estado global de la aplicación React (Context API, Redux, etc.).

7.19 T

Tailwind CSS
Framework de CSS utilitario para estilos rápidos sin escribir CSS tradicional.
Template
Archivo HTML que define estructura. En PIT también contiene el Frontend React.
Token
Cadena encriptada que prueba autenticación del usuario. Enviado en cada request.
Turista
Usuario final que consulta información turística. Tiene acceso de solo lectura.

7.20 U

URL (Uniform Resource Locator)
Dirección de un recurso en internet. Ej: http://localhost:8000/api/atractivos/
Ubicación
Información geográfica de un atractivo (latitud, longitud, dirección).
UUID (Universally Unique Identifier)
Identificador único global, a menudo usado en lugar de IDs numéricos simples.

7.21 V

Validación
Proceso de verificar que datos enviados cumplen con reglas (formato correcto, campos obligatorios, etc.).
View
En Django, componente que maneja lógica de un endpoint HTTP.
Vite
Herramienta moderna de construcción (bundler) para proyectos web. Más rápida que Webpack.

7.22 W

Webhook
Llamada HTTP automática que se dispara cuando ocurre un evento.
WebSocket
Protocolo para comunicación bidireccional en tiempo real entre cliente y servidor.

7.23 Z

Zoom
Función de mapas para acercarse o alejarse de un área.
